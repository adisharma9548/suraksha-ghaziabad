# Architecture & Implementation Decisions

## 1. Platforms Supported
- **Mobile Only (Android first, iOS-compatible codebase)**: As strictly instructed, no web, Windows, macOS, or Linux targets. If generated by default Flutter tooling, web, windows, linux, and macos directories are purged. Only `android/` and `ios/` folders remain.

## 2. Portrait Orientation
- Locked to portrait orientation (`DeviceOrientation.portraitUp`, `DeviceOrientation.portraitDown`) in `main.dart` to adhere to the 360x800 dp mobile form factor.

## 3. Abstract Repository & Mock Implementation First
- To guarantee the application works end-to-end with zero cloud dependencies or setup friction, all data access is mediated through an abstract Repository layer:
  - `AuthRepository`
  - `SosRepository`
  - `ReportRepository`
  - `PatrolRepository`
  - `HelpPlacesRepository`
  - `TripRepository`
- An in-memory/persistent `Mock` repository implementation is default. A single configuration flag (`AppConfig.useFirebase`) toggles between Mock and live Firebase services.
- `MockSosRepository` features real-time stream simulation, broadcasting live status updates, simulated location coordinates moving along road paths, and audio simulation.

## 4. Maps & Heatmap Layer
- Used `flutter_map` with OpenStreetMap raster tiles (no paid key or API token required).
- Heatmap rendering: Implemented a high-performance custom canvas heatmap overlay (`HeatmapCanvasLayer`) on top of OpenStreetMap coordinates. It weights incidents by severity and clusters nearby reports with gradient color blending (Green -> Amber -> Red).

## 5. Offline & SMS Fallback
- During an SOS trigger, if network connectivity is down or in Mock mode, the app generates an urgent SMS intent payload containing the user's name, timestamp, and accurate GPS Google Maps link (`https://maps.google.com/?q=lat,lng`) using `url_launcher` `sms:` URI scheme to reach all configured trusted contacts.

## 6. Fake Call Simulation
- Built-in realistic incoming caller UI with customizable delay (5s, 15s, 30s, 60s), customizable caller identity (e.g. "Papa", "Bhaiya", "Police Station Ghaziabad"), realistic full-screen Android phone call UI, ringtone haptics, and simulated caller audio dialog.

## 7. Officer Role Integration
- Both citizen and officer roles reside inside the exact same mobile application. On the login screen, a discreet yet clear "Officer Login" entry leads to the police terminal screen with credentials `OFFICER01` / PIN `1234`.
- Officers can view live incoming SOS alerts in real time, view live citizen GPS moving tracks, assign nearest patrol vehicles automatically calculated via Haversine distance, update citizen report statuses (Open -> In Progress -> Fixed), and review Ghaziabad crime analytics.

## 8. Demo Mode
- A persistent Demo Mode switch is included in Profile & Settings.
- Automatically seeds ~60 realistic unsafe spot reports across major Ghaziabad localities (Raj Nagar, Vaishali, Indirapuram, Kaushambi, Sahibabad, Crossings Republik, Vasundhara, Mohan Nagar, Kavi Nagar, Govindpuram).
- Adds a "Simulate Officer Response" control on the SOS Active screen, enabling judges/testers to step through the entire SOS emergency lifecycle without needing a second device.
